Brian (2026-06-18, on two `proposal_sent` deals sitting with no dollar value): "when you send a menu, choose a middle of the road option and assign to that deal, like for rev1, i'd do $5K. Since we sent graymatter a package, i'd assign the deal to the package."

**The rule (applies the moment a proposal/quote goes out, i.e. stage `proposal_sent` or later):**
- **Menu of options sent** → book the **middle-of-the-road** option as the deal value (the sensible central recommendation, not the cheapest and not the top outlier). Rev1 menu was Custom Article $5K / SF Tech Week $15K / $6K / Happy Hour table $5K → value = **$5,000**.
- **A specific package recommended** → book the **package price**. GrayMatter got a recommended 1-month trial package (1-mo Partner Program + 2x Primary) at $5K → value = **$5,000**.
- **Never leave a `proposal_sent`/`contract_sent`/`negotiation`/`closed_won` deal with an empty value.**

**Why:** an unpriced deal at proposal stage contributes $0 to the pipeline total and reads as at-risk / hygiene-F even though a real priced proposal is already out the door, so the pipeline understates the business. This is the flip side of [[feedback-no-phantom-pipeline]]: leave value empty *before* a price is sent, but once a menu/package has actually gone out it's a real quote, not a phantom estimate, so assign it.

**How to apply:** when running `scripts/console-pipeline-update.mjs` after a post-call follow-up, always pass `--value`. Don't rely on the script's built-in middle-of-three auto-picker — it only fires when the evidence text has exactly three dollar figures, so menus with four+ options (Rev1) or many rate-card lines (GrayMatter) fall through to null. I (the agent) pick the middle option / package price and pass it explicitly. Picking the number is a judgment call, not a regex job.
