The kerrihq-rails workspace lives at `~/Projects/kerrihq-rails` (cloned 2026-06-10; Phase 1 cleanup landed on branch `phase-1-cleanup`).

This machine had no Ruby/Postgres toolchain before 2026-06-10 (Don developed elsewhere). Installed via Homebrew:

- **Ruby 4.0 (plain `ruby` formula) as of 2026-07-01**: the bundle was re-installed under `vendor/bundle/ruby/4.0.0`, so plain `bundle exec` with NO PATH export is what works now. The old ruby@3.4 export BREAKS bundler (GemNotFound — no 3.4.0 dir in vendor). BUNDLE_PATH is `vendor/bundle` via `.bundle/config`.
- PostgreSQL 17: `brew services start postgresql@17` (pg bin PATH export no longer needed for rspec; psql itself may still need it)
- Yarn 1.22 (classic) via brew; Node 26 already present

**Parallel-session hazard (bit us 2026-07-01):** multiple Claude sessions share this checkout and switch branches under each other — a commit landed on another session's branch. Use a dedicated worktree per workstream. The quiet-console redesign lives in `~/Projects/kerrihq-rails-quiet-console` (worktree on `redesign/quiet-console-*` branches; `vendor/bundle` + `node_modules` symlinked to the main checkout, built assets copied into `app/assets/builds/`). Always check `git branch --show-current` immediately before committing in the shared checkout.

`config/master.key` is absent on this machine, so credential-dependent code paths fall back to ENV. Test suite + bin/ci run fine without it. `bin/ci` was fixed 2026-06-10 to run RSpec (it previously ran the empty Minitest suite).

**Why:** Saves re-discovering the toolchain every kerrihq-rails session.
**How to apply:** cd to the repo, use the PATH export, then bundle exec rspec / bin/ci as normal. Related: [[kerrihq-console-takeover]] (plan context lives in the session plan file).

`gh` CLI IS authenticated on this machine (verified 2026-06-17: `gh auth status` → logged in as `Brianderario`, keyring token, https). PR listing/creation via `gh` works for both `Brianderario/kerrios-agent-brain` and `kerrihq/kerrihq-rails`. (Superseded the prior 2026-06-11 note that gh was unauthenticated.)
