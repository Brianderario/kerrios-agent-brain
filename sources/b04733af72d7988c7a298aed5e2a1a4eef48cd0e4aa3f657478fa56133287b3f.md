**Architecture:** `SelfUpgrade` ledger model (tiers: autonomous = her prompt/tools/playbooks; approval = other app code; protected = safety rails incl. the pipeline itself, .github, config, db, Gemfile → always a `harness_change` ApprovalRequest for Brian). `SelfUpgrades::Runner` gates: workspace sandbox runs `bin/rubocop` + `bin/rails eval:agent` against the EDITED code (eval cases roll back their transactions, prod-safe) → PR (full CI) → merge (CodeShippingClient already refuses non-green/non-Kerri PRs) → `SelfUpgradeCanaryJob` 15-min canary (AgentRun failure spikes + tool-dispatch smoke; 2 strikes → rollback ALL Render services via `RenderClient`, kill switch auto-OFF, urgent owner task). Dead-man: `.github/workflows/self_upgrade_watchdog.yml` probes prod every 10 min from GitHub infra; dead fresh deploy → Render rollback + task. Kill switch `PlatformSetting.self_upgrade_enabled` ships OFF.

**Dogfood lesson (important for ALL prompt work):** verbose tool descriptions/guidance measurably cost the glm-5.2 agent marginal eval points (3 runs, 3 different 9/10 drafting failures; clean main baseline; trimming text → ALL GREEN). Keep new tool schemas and prompt bullets terse; always baseline-compare eval flake before blaming/absolving a change.
