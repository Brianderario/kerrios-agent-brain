**Architecture (the load-bearing fact):** the training loop already existed — `VoiceCalibration`
(weekly job) distills Brian's edits into an `AgentVoiceProfile` that `system_prompt.rb:110-116`
injects into every draft. It just had no *score* and never learned from approvals/rewrites. This
work adds the missing scoring layer and feeds it in; it does NOT add a parallel system or a new
injection path.

- `DraftFeedback` model + `draft_feedbacks` table = one scored row per decision. Scoring is
  deterministic/explainable (`Drafts::Scoring`, token similarity, no LLM): approve-clean=100,
  approve-edited=100×similarity clamped [40,99], rewrite=15, skip=no score (triage, not quality).
- Capture is best-effort in `TasksController#approve/#redo/#skip` (`Drafts::RecordFeedback`),
  rescue-wrapped so it can NEVER break the send path.
- `VoiceCalibration` extended: learns from rewrite guidance, weighs edits by severity, uses
  approval rate to calibrate ambition. Still style-only, versioned, revertible (`rake voice:revert`).
- Backfill: `rake draft_feedback:backfill` (reads task_events); readout: `rake draft_feedback:stats`;
  the weekly voice-calibration digest now shows the quality trend.

**Post-merge:** run `rake draft_feedback:backfill` once to seed history; next Monday's
VoiceCalibrationJob picks up the enriched signal automatically.

**Deferred follow-ups (documented in PR, not shipped):** (1) stamp `model_tier` onto drafts at
`create_task` time to populate by-model scoring — the tier lives in the agent/schedule layer, not
`tool_executor`, so it needs threading; (2) optional few-shot injection of approved exemplars into
the drafting prompt (exemplar data already captured on `DraftFeedback`).
