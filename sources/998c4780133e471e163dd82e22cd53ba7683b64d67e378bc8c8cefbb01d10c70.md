Fix for "agents start new email chains by replying with Re: [Subject]" (Brian, 2026-07-06). Root cause: `SendApprovedDraftsJob` (kerrihq-rails, the deterministic sender for every Brian-approved draft: draft → approve → auto-send, the dominant Slack-agent reply path) only ever called `send_message`, and approval cards never captured the message being replied to — so every approved reply went out as a brand-new email. The interactive `reply_mail` tool already threaded; only the approve-queue path was broken.

Fix (PR #444, squash `edc858e`; MERGED + DEPLOYED to prod 2026-07-06, both Render services live):
- `create_task` accepts `reply_to_message_id` / `reply_to_mailbox` / `reply_to_conversation_id` and stores them in the card's **`source_details`** (survives approval; `resolution_payload` does NOT — the approve action in `tasks_controller#approve` replaces it with `{}`+edited_body). Also lights up the card's existing "open thread" link via `TaskEmailThreadReference`.
- `SendApprovedDraftsJob` reads that reference and sends replies via `reply_message` (provider-native threading, reply-all recipients). Non-reply sends and `Fwd:` forwards still use `send_message`.
- Backstop hold: a `Re:` draft with NO thread reference → held to `needs_approval` with `held_reason: "reply_as_new_thread"` (never bare-sent as a new chain). `Fwd:` excluded on purpose.
- `create_task` warns the agent at creation time when a `Re:` reply draft omits `reply_to_message_id`; tool schema + system prompt tell it to always pass it. `Outbound::PreSendCheck.reply_subject?` (Re-only) centralizes the test.

**Why:** matches the [[presend-check-coded]] doctrine — a permanent email rule belongs in code, not a prompt (coded gate > prompt rule). Threading was structurally impossible before because the card carried no message-id to reply onto.

**How to apply:** when the sweep/agents file a reply card, they MUST pass `reply_to_message_id` (+ `reply_to_mailbox`) or it holds on send. Rollout: pre-existing approved reply cards without a reference will hold (safely) rather than start a new chain until re-filed.
