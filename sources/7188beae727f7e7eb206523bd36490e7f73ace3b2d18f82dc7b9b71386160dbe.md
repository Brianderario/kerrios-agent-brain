The Slack agents (Kerri + Oliver — the Rails Savant agent on Ollama glm-5.2, see [[slack_agents_architecture]]) can now **read file attachments** users post in Slack. Shipped [kerrihq-rails#205](https://github.com/kerrihq/kerrihq-rails/pull/205), merged to main (c1fa4c65a) + deployed live 2026-06-29. Worktree `~/Projects/kerrihq-rails-superhuman`.

`Slack::AttachmentReader` downloads the inbound message's files via `Slack::Client#download_file` (url_private_download + bot token) and extracts text: text-family files, PDFs (`pdf-reader` gem added, pure Ruby), and .docx (rubyzip+nokogiri, already vendored). Model is text-only so images/binaries are noted as unreadable, not guessed. Bounded: ≤5 files, 10MB/file, 12k chars/file, 36k total (under the 38k Slack budget). Fails soft (unreadable file → short note, never a crash). `EventProcessor` splices extracted text into the answered turn and no longer ignores a caption-less file post. Applies to all workspaces (Slack-layer, not tool-gated).

**files:read scope status (checked via X-OAuth-Scopes 2026-06-29):** Kerri (`SLACK_KERRIHQ_BOT_TOKEN`) = YES → works now. **Oliver (`SLACK_OLIVER_KERRIHQ_BOT_TOKEN`) = NO** → Oliver degrades to "can't read that file" until `files:read` is added to the Oliver Slack app (api.slack.com/apps → OAuth & Permissions → add files:read → reinstall → the reissued xoxb token must replace `SLACK_OLIVER_KERRIHQ_BOT_TOKEN` on the Render worker+web). HWFYI app already has files:read. Same manual-scope pattern as the pending users:read ([[kerri-slack-bot]]); can be driven via Brian's Chrome.

Verified: 273 specs green, rubocop/brakeman clean, real-PDF + real-docx extraction tested end-to-end (not just mocks).
