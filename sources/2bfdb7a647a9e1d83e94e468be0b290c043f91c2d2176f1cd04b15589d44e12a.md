The event/venue/vendor cards on Brian's Console are filed **freehand by the Savant/Slack Kerri agent via `AskSavant::ToolExecutor#create_task`** in `kerrihq-rails`, NOT by the local `kerri-event-logistics` skill. That skill's file flow (`data/events/<slug>/`) is unused/empty; agent-filed cards show `agent_slug: none`, `external_ref: none`, `source_details.created_from: slack`. So any behavior fix for these cards must land in **kerrihq-rails**, not the local skill (matches [[feedback_style_changes_to_routines]]).

There are TWO create paths, both now sharing `Tasks::VendorCard`:
- `AskSavant::ToolExecutor#create_task` (the Slack/Savant agent — the real one)
- `Tasks::CreateTaskTool` (MCP/`/api/v1` surface)

**VendorCard discipline (SHIPPED + LIVE on Render, commit `adc959e`, via PR [#238](https://github.com/kerrihq/kerrihq-rails/pull/238); the first attempt PR #237 squash-merged EMPTY due to PR-number contamination from a concurrent agent worktree, so always verify the merge commit actually contains your files):**
- `outbound_attachments` / `inbound_attachments` params render a fixed `📎 ATTACHMENTS` block; a draft that says "attached" with nothing outbound is rejected (mirrors `scripts/presend-lint.mjs` check #4, draft-body only).
- `event_slug` + `event_name` + `vendor_category` auto-group cards under one per-event-per-category master tracker via `Task#linkable` (deterministic `external_ref` `kerrios:event:<slug>:<category>:master`, live count + status rollup). One master per category (catering, av, venue, ...).

Tasks table has no parent/child column; grouping uses the polymorphic `Task#linkable`. `TaskNotes` parses the sendable-draft body; `send-reply` IS a valid `SEND_ACTION` there.
