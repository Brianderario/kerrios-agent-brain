Shipped 2026-06-30 (PR #233, merged + deployed; prod table + first profile live). Answers "where can the agent teach itself to produce better output vs what I actually send." Brian chose **auto-apply + weekly digest**.

**How it works:**
- `AgentVoiceProfile` (table `agent_voice_profiles`, versioned, org-scoped): the active profile's `guidance` is injected into `SystemPrompt.build` (after the writing-style rule), so EVERY draft — live + scheduled — uses Brian's learned voice automatically. History kept for revert.
- `VoiceCalibration` (`app/services/voice_calibration.rb`) mines two signals: (1) draft cards Brian EDITED in the Console before approving (`resolution_payload.edited_body` vs the agent's original draft — the cleanest supervised pair), and (2) a sample of his SENT mail from KMG mailboxes only (brian@/kerri@/info@ hardwarefyi, Graph folder **`sentitems`** not `sent`). NEVER S/W (Superhuman) or personal — S/W boundary. Distills STYLE rules only via the strong model; no client names/prices/content/raw mail stored.
- `VoiceCalibrationJob` weekly (recurring.yml `13 8 * * 1`): runs it, activates the new profile, DMs Brian a digest + one-line revert.
- Revert: `revert_voice_profile` agent tool (Brian-only, Slack) + `rake voice:run/show/revert`.

**Safety:** auto-apply only touches DRAFTS, which Brian approves before anything sends — a bad profile can't send bad mail, and revert restores the prior. The edits Brian makes feed the NEXT calibration (compounding).

**First live profile (c50e3c00…, 2026-06-30):** 11 edits + 15 sent emails → 14 leak-free voice rules (soften scheduling pushes, one clear ask not a menu, short follow-ups don't re-pitch pricing, vary sign-offs Brian/Talk soon!, fill placeholder links before sending, mention new offerings organically). Verified injected into the live prompt.
