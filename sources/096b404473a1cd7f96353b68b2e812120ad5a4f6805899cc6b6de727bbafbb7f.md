Shipped 2026-06-30 (PR #225, merged to `kerrihq-rails` main, Render + Mac-mini worker on it). The #1 reliability gap from the OSS-harness research: our ~1,970 specs test the CODE, this tests the AGENT'S BEHAVIOR so prompt/model changes get regression-tested before shipping.

**Where:** `app/services/agent_eval/` (Runner, GoldenCases, Checks, Judge, Report, Sandbox, SlackDelivery) + `app/services/mailbox_capture.rb`. Specs: `spec/services/agent_eval/`, `spec/services/mailbox_capture_spec.rb`, gated live spec `spec/live/agent_eval_live_spec.rb`.

**Run it:**
- `RUN_LIVE_EVAL=1 bundle exec rspec spec/live/agent_eval_live_spec.rb` (needs OLLAMA_API_KEY; source `.env.mac-mini`).
- `EVAL_DM=1 bundle exec rake eval:agent` — runs + DMs Brian the scorecard. Exits non-zero on regression (can gate a deploy). Takes ~10-12 min (5 cases x live model).

**How it's safe:** each case runs the REAL `AskSavant::Agent` loop inside a transaction that always rolls back (nothing persists), with `MailboxCapture` active so the mail clients serve a fixture inbox + capture outbound instead of hitting the network (fails closed, inert in prod). Each mail-client network method has one no-op guard. Prefer a non-prod DB (a live model call holds the tx open briefly).

**5 golden cases / checks:** draft-reply-voice, sweep-inbox, morning-brief-html, external-send-gated, dedupe-draft. Deterministic checks (no em dashes in deliverables, HTML-not-code, cards parse sendable via TaskNotes, dedup holds, send gate) + LLM judge (voice, sweep triage; JSON with retry + prose-score fallback because glm-5.2 reasons past its token budget).

**Baseline 2026-06-30: 5/5 cases green** after calibration. Add a case here whenever we fix a behavior we don't want to regress.

**Harness reliability additions (PR #230, merged + deployed 2026-06-30):**
- **Parallel subagents** — `run_subagents` tool fans out up to 6 INDEPENDENT research subtasks concurrently, each a fresh `AskSavant::Agent(subagent: true)` with isolated context + a READ-ONLY toolset (`Tools::SUBAGENT_TOOL_NAMES`; no sends/writes/code-ship/connector-mutation/recursion). Concurrency cap 3 (`ASK_SAVANT_SUBAGENT_CONCURRENCY`), each thread checks out its own DB connection; `MailboxCapture.with_session` propagates capture into child threads. Live-verified: 3 subagents in 6.9s. RAILS_MAX_THREADS=10 set on Render web+worker + Mac-mini `.env.mac-mini` (PR #231) for pool headroom.
- **Planning checkpoint** — every 6th iteration on a long task, a SYSTEM message asks the model to restate goal + remaining steps. `PLANNING_CHECKPOINT_EVERY` (default 6; was 4 but that interrupted ~4-step tasks like the morning brief at the send boundary — fixed). Skipped on subagents, past deadline, and during code-ship.
- **Run-to-completion `ensure_draft_filed`** — if the final answer is a canonical sendable draft but `create_task` never fired, files it deterministically (needs_approval, dedups). Only catches CANONICAL-format drafts; if the model writes a reply as plain prose it still won't file (model variance the eval surfaces).
- **Nightly eval** — `AgentEvalNightlyJob` (recurring 4am) runs the suite, persists `AgentEvalRun`, DMs Brian result + trend vs last. `rake eval:nightly` (run now), `rake eval:history` (trend). prod `agent_eval_runs` table live.

**DEFERRED (own future ship):** dynamic tool loading (ToolSearch-style on-demand tools) — larger architecture change, gap #6's other half.

**FINDING from live Slack smoke test (2026-06-30):** asked open-endedly to "do deep research" comparing 3 companies, Kerri answered from PARAMETRIC MEMORY without calling research_web OR run_subagents — fast + plausible but UNGROUNDED. When told explicitly to "use run_subagents," she did it perfectly (3 parallel subagents → 6 web searches, grounded with sources, ~35s, no errors — confirms the feature works live through Slack). So the gap is tool-CHOICE: she doesn't reliably reach for research/subagent tools on her own for research-type asks. Candidate fix: a system-prompt rule to ground research requests with tools + consider run_subagents for 2+ independent items; add a golden eval case for it. Smoke-test perf: lookups 6-9s, draft+file 35s, no slowdown from the harness additions.

**Findings the eval surfaced:**
1. FIXED (PR #227, 2026-06-30): the machine-sendable card format was taught ONLY by routine prompts, not the base tooling, so interactive drafts could be non-sendable (dedup + send job would skip them). Baked the format into the `create_task` tool description (`Tools::SENDABLE_DRAFT_FORMAT`, conditional on it being an email draft). Live-verified: draft-reply-voice + external-send-gated file sendable cards from tooling alone, no prompt hints.
2. DISCARDED (Brian, 2026-06-30): em dashes leak into the agent's CHAT text. Brian doesn't care about em dashes in chat — only deliverables. The eval's NoEmDashes check already scans only deliverables (drafts/sends), not chat. No enforcement on chat.
3. OPEN (model variance, not a regression): on longer tasks (the inbox sweep) the agent occasionally composes the reply in chat but never calls `create_task` to file the card (1 miss in ~4 runs; filed correctly on 2/2 re-runs). Run-to-completion characteristic of glm-5.2. Candidate: a "file the card" run-to-completion nudge.
