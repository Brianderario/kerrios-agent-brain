When a request includes producing an asset or taking an action (not only a reply), build it to completion in the same turn, verify it, and deliver the finished artifact to whoever asked (Brian, Zach, Ari, Benji). The chat or email reply is the cover note, never the deliverable.

**Why:** A background executor *does* exist (23 cron scheduled-tasks + 5 launchd agents), but it runs pre-authored routines on cold start; it does NOT carry an ad-hoc promise I make inside a chat or email turn. So "I'll send it" has nothing behind it unless I write that hand-off into a durable artifact (a one-time scheduled task or a Console card) in the same turn. The promise otherwise evaporates when the turn closes. Brian is non-technical and does not read the work, so a bare promise reads as done while producing nothing, and the gap stays invisible until the file never arrives. This burned the Ironclad sponsorship one-sheeter: the PDF already existed at `~/Projects/ironclad-maritime-site/promo/` and was correct, and I still only replied instead of delivering it.

**Now enforced (2026-06-19):** check #5 of the [[presend-lint-gate]] hard-blocks any outbound mail that promises a deliverable later (defer verb + asset noun) with nothing attached. Email-borne version of this failure is now mechanical, not memory-dependent. Promises made purely in chat (no email) are still on me to honor in-turn.

**How to apply:** (1) Split every request into reply-part and do-part; the do-part is the real task. (2) Finish and verify the artifact in-turn. (3) Hand over the actual file or link (SendUserFile, attachment, or a staged draft that already contains the asset), not a description of it. (4) If an external send is the last step, stage it fully so only Brian's approval remains, and say "it's built and in hand, one approval from sent," never "I'll do it." (5) If it genuinely cannot be finished in-turn, create a durable task with the blocker and ETA, and say so plainly.
