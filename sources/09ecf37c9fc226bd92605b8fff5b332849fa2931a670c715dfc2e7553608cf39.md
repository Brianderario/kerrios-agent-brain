Kerri (Slack agent) got stuck applying it herself: her `serialize_agent_schedule` omitted the prompt field, so she saved the rule to agent memory (which scheduled runs don't obey), the prod schedule prompt never changed, and her confirmation posted as an empty Slack message.

**PR #274 merged + deployed 2026-07-01 ~7:00 PM ET** (Render web + queue, commit 4b2f684). First post-deploy sweep failed on Ollama rate limiting, which exposed a follow-up bug: failed runs advanced `last_finished_at`, so the watermark would skip mail arriving during a failed run's window. Fixed in PR #278: watermark = newest **succeeded** AgentRun scoped by `external_id LIKE 'agent-schedule:<id>:%'`; failed runs leave the cutoff untouched.

**2026-07-03, draft-don't-describe fix:** the sweep was filing reply-worthy mail as descriptive to-dos ("Brian needs to reply with the specs...") in the action_needed lane instead of drafted replies in needs_approval ("Needs Brian"). Fixed in both layers: (1) prod prompts — a "DRAFT, DON'T DESCRIBE" section added to both sweep schedules (write the reply, file sendable format, status needs_approval; plain to-dos only for non-email work; missing facts go in one [MISSING: ...] line, never a stub card); (2) code (PR #330, live) — create_task now defaults a sendable draft with no explicit status to needs_approval (the tasks table column default is action_needed = hidden drafts), and returns a non-blocking `warning` on reply-shaped cards that carry no draft so the agent self-corrects in-turn. The misfiled Aris Machina specs card was rescued by hand (drafted via kerri-reply-drafter, PATCHed to sendable + needs_approval).
