When recommending software, do NOT propose building standalone apps, web dashboards, or new chat/task surfaces (including Slack-as-interface). Brian has tried ~3 apps in 7 months building KerriOS and all failed.

**Why:** On a 3-person non-technical team, anything with its own UI carries a tax — someone must choose to open it, learn it, and maintain it. That tax always exceeds the friction it removes, so the tool rots. "Just ask Kerri" beats every standalone surface. High task volume makes any chat/queue surface a firehose, not a fix.

**How to apply:** Build only two things — (1) invisible glue (scripts/routines with no screen, e.g. Tito→CRM sync, Stripe→sheet sync, deliverables watchdog) that move data and feed surfaces Brian already reads; (2) improvements *inside* tools he already opens daily (Google Tasks, the Sheets, email, the morning brief). Kerri is the interface; existing tools are the only surfaces. The fix for queue overload is raising Kerri's autonomy bar (auto-handle low-judgment work, escalate only genuine judgment calls), not a better-looking queue. If a task ever seems to need a screen, that's a signal the autonomy boundary is wrong, not that we need an app. Google Tasks is intentionally used as agent-scoped work queues; respect that structure.
