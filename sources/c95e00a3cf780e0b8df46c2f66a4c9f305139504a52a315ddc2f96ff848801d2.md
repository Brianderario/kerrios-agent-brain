When a Hardware FYI newsletter sponsor sends creative (logos, ad copy, CTA), file it and link it in three places:

1. **Google Drive** — parent folder **"Sponsor Deliverables"** (id `18yaF7m64PbUQe2FTci-W-P47OlLu0aAb`), one subfolder per sponsor named "`<Sponsor>` Assets" (e.g. "Protolabs Assets", "Duro Assets" id `1hBJL-VIEx4F98NufPtImPiXA_SEBsaID`). Put the logo files plus a short "`<Sponsor>` - Newsletter Creative & Assets" Google Doc (verbatim blurb, CTA/UTM link, placement schedule, logo inventory, source email).
2. **HWFYI CRM sheet** (`1mXauTrY5fTgQURfCE1VU2u65hc5nxd6waRVss-mcgYk`) -> tab **"Newsletter Ad Calendar"** (this is what Brian calls the "Newsletter Inventory" tab) -> **col G "Assets"** -> the Drive folder URL on that sponsor's primary-placement rows. Flag sponsors with nothing filed as "Not filed in Drive".
3. **Savant** — append the folder link to the sponsor's **deal notes** via `PATCH /api/v1/deals/:id` (scope `deals:write`; read-modify-write to preserve existing notes). The proper SponsorAsset model (external_url on a sponsor_commitment) exists, BUT: the agent API can't create SponsorAssets, `POST /api/v1/newsletter_inventory_imports` CLOBBERS commitment starts_on/ends_on/value/notes when sent a partial row (no blank-guarding), and the `/newsletter_inventory` UI 404s in prod (not deployed as of 2026-06-24, pending [[savant_full_qa_2026-06-22]] PR #123). Use deal-notes until that page ships.

**Email attachment -> Drive without base64 passing through context:** mint a Graph app-only token from the email MCP creds (`~/.kerri-chief/kerri-hardwarefyi-email-mcp/.env`: GRAPH_TENANT_ID/CLIENT_ID/CLIENT_SECRET, client_credentials, scope `.default`), GET `/users/<mailbox>/messages/<id>/attachments/<aid>/$value` to /tmp, then upload via kerri-gdocs OAuth googleapis `drive.files.create` (kerri-gdocs CAN write into folders the google-drive connector created). Template script: `/tmp/duro-upload.mjs`. First done for Duro 2026-06-24.
