Savant/Slack Kerri has a deterministic memory router: `app/services/memory_policy.rb` (`MemoryPolicy.classify`) gates every `remember_agent_memory` / `remember_brain` call in `app/services/ask_savant/tool_executor.rb`. It scores content as agent-operating-rule vs company-knowledge so a bad tool choice can't poison the wrong store.

**2026-06-30 fix (PR #241, `fix/agent-memory-honor-and-mirror`):** `remember_agent_memory` used to hard-reject any save classified as company knowledge ("That belongs in candidate company brain memory... No memory was saved") and save nothing. Orienting facts Brian wanted Kerri to have loaded (team roster, brands, events, purpose) all scored as company knowledge and bounced repeatedly. Now it only refuses true noise (secrets/dumps/personal-health-identity); otherwise it honors the explicit request to keep the fact in Kerri's private operating memory AND mirrors a review candidate into the shared brain via `remember_brain`. Mirror failure never fails the private save. MemoryPolicy classification is unchanged; the reverse guard (agent operating rule sent to the brain still routes back to private memory) is unchanged.

**Brain promotion is human-only by design.** `Api::V1::KnowledgeRecordsController` requires `brain:write` for create/update, agents can only file `candidate`/`imported` status, and `update` strips `:status`. So even with `brain:write`, the API can create/edit candidates but CANNOT flip candidate → canonical. Promotion happens in the Savant `/brain` UI (owner/master access) only. `KERRIHQ_AGENT_API_KEY` has `brain:read` + `brain:write` + `agents:write` (per MEMORY.md index), so it can file candidates but not promote them.
