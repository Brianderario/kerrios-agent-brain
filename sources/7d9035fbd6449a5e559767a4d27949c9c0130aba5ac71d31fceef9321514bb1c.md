Before drafting any post-call follow-up email, do a full research sweep using available tools and inventory every promised deliverable. Never ask Brian what was discussed on a call. Never draft a placeholder email.

**Why:** On 2026-06-17, Brian flagged that Protolabs (H0106), Kickstarter (H0154), and C-Infinity (H0119) follow-ups were all empty placeholders when the information was already accessible through Granola transcripts, Drive documents, brain wiki pages, and local files. The final sent versions contained metrics reports, audience data, packages with pricing, customer overlap lists, attendee lists, and media kits. All of it was available before the first draft was written. Kerri defaulted to "I'll send details" instead of doing the research to include the details.

**How to apply:**
1. Before drafting any post-call follow-up, read `brain/wiki/workflows/post-call-followup-protocol.md` (mandatory).
2. Pull the Granola transcript. Read the email thread. Read relevant brain wiki pages (audience, pricing, playbook). Search Drive. Check local files.
3. Inventory every deliverable Brian promised on the call. For each one, determine if you have it, can produce it, or need to request it from Brian.
4. Draft only when you can deliver everything in one email. If something is genuinely missing, request it from Brian before drafting.
5. Run the completeness test: does this email give the recipient everything they need to make a decision?

Component (step 3) of the [[definition-of-done-gate]] pre-send gate. Related: [[feedback-followups-complete]], [[feedback-post-call-followups]], [[feedback-attach-what-you-have]].
