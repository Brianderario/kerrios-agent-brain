Before drafting or sending anything Kerri composes (everything except Brian's verbatim words), run this gate in order. It consolidates five separately-codified rules into one motion so the behavior is a single checklist, not five things to remember.

1. **Read the full state first** — the whole thread + Brian's last message, then `NOW.md` and `brain/log.md` for the topic. The message must reflect what's already done or in flight. ([[brain-log-check-before-send]])
2. **Name the real deliverable, not the nearest reply** — package with prices, contract, metrics report, customer list, roster. The deliverable is the thing, not an email promising the thing. ([[feedback-followups-complete]])
3. **Research + inventory before drafting** — for post-call follow-ups, mandatory: pull Granola, thread, wiki, Drive, local files; never ask Brian what was discussed. ([[feedback-postcall-research-first]])
4. **Attach what we already hold** — if a promised file exists on disk, attach it and say "I have attached", never "I will send". ([[attach-what-you-have]])
5. **Completeness test** — does this give the recipient everything to act, in one message? If not, do not send a partial.
6. **If blocked, escalate, never park** — email Brian the four-part request (task / who / exact thing needed / what it unblocks); in interactive sessions, often doable via Chrome takeover. ([[feedback-escalate-on-block]])
7. **Restate before send** — lead the card/chat with one line: `Deliverable: X. Pulled from: …. Attached: Y.` so Brian catches thin context in 5 seconds.

**Why:** The 2026-06-17 weekly retro found ~25% of net-new asks opened with a correction, and nearly all were ONE root cause in different costumes: a holding output instead of the finished deliverable, and acting before reading existing state. Brian: codify them as one gate "so my pre-send behavior actually changes rather than this being a nice memo." Maps to his "complete fulfillment, always verify" standard. **How to apply:** Run the seven steps before every composed send. If a new correction in this class appears, extend this gate, do not mint a parallel rule. Component detail lives in the five linked feedback memories. See also [[coding_standards]] (complete fulfillment).
