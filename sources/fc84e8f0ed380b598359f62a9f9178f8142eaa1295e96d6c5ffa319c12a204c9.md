Kerri can now WRITE to the Savant brain over the API (not just read). Granted 2026-06-30.

**How to create a record:**
`POST https://kerrihq-rails-xtua.onrender.com/api/v1/knowledge_records` (Bearer `KERRIHQ_AGENT_API_KEY`), body shape:
```
{ "domain": "<domain_key>",            // TOP-LEVEL, not nested. e.g. hardware_fyi, standard_works, operations, pipeline, engineering, events, global, people, finance, legal
  "knowledge_record": { "kind": "<KINDS>", "title": "...", "summary": "...", "body": "...", "sensitivity": "normal_internal", "status": "candidate", "citation": "..." } }
```
- Agents file `status: candidate` or `imported`. **Promotion to canonical is now possible over the API** for a key carrying the `brain:promote` scope (PR #421, live 2026-07-06): `POST /api/v1/knowledge_records/:id/promote`, `POST /api/v1/knowledge_records/promote_batch` (body `{ids:[...]}`, per-id outcomes: promoted/already_canonical/not_found/forbidden/error), and `DELETE /api/v1/knowledge_records/:id` (drafts only, needs `brain:delete`). Our interactive key `krri_f87b3f35` (`KERRIHQ_AGENT_API_KEY`) was granted `brain:promote`+`brain:delete` on 2026-07-06, so Kerri can promote/curate on Brian's approval. Keys without those scopes (background/per-agent) still cannot self-promote; acting agents are still bounded by their update grants. Canonical/superseded records stay non-deletable via API (Savant only). The `/brain` UI `KnowledgeRecord#promote!` path also still works.
- Valid `kind` values: person company workflow decision project deal event meeting_note property revenue_record editorial_rule approval_policy agent_instruction source_pointer memory candidate_memory operational_doc raw_evidence.
- Optionally pass top-level `agent_slug: <slug>` to attribute the write to a specific agent (subject to that agent's grants). Omit it and the record is `imported_from: "api"`.
- No em dashes in record bodies.

**How the scope was granted:** the `brain:write` scope was added to the `ApiKey` row (token prefix `krri_f87b3f35`) via a Render one-off job on service `kerrihq-rails` (`srv-d8kvn767r5hc739fjo9g`), using `RENDER_API_KEY` in `~/.kerri-chief/secrets/render.env`. Pattern: `POST /v1/services/<svc>/jobs` with a `bundle exec rails runner` startCommand; poll the job, read stdout via the Render logs API.

**Bug fixed along the way (PR #240, merged + deployed 2026-06-30):** `POST /knowledge_records` from a plain (non-agent) key used to 500 with `undefined method 'slug' for false` — `acting_agent` returned `false` instead of `nil` so `false&.slug` raised. Fixed in `app/controllers/api/v1/knowledge_records_controller.rb`. If agentless brain writes start 500-ing again, check that regression.
