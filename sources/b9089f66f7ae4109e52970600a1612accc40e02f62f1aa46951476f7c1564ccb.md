`Outbound::PreSendCheck` (kerrihq-rails, PR #317, 2026-07-02) hard-enforces Brian's locked-in email rules on every send, before and regardless of approval: (1) sign-off matches sending mailbox (kerri@→Kerri; brian@hfyi/brian@kerrihq/info@→Brian; benji@→Benji), (2) send_mail with Re:/Fwd: subject rejected → use reply_mail, (3) reply must target the newest thread message, (4) reply resolving to internal-only recipients rejected when the thread has external participants, (5) reply_all:false needs narrow_reply_reason. Overrides (confirmed_new_thread, allow_older_message, internal_only, narrow_reply_reason) are explicit + audited. Wired into ask_savant send_mail/reply_mail (before the confirmation gate) and SendApprovedDraftsJob (holds card with held_reason signoff_mismatch).

**Why:** prompt-level rules don't enforce. Kerri saved the rules as an agent memory at 01:28 UTC; at ~02:00 a Doss reply still went To=benji@ (reply-all resolved recipients from a teammate's message; seb@doss.com never got it); she wrote a stronger AgentProgram at 02:04. Only code inspecting what reply_mail actually resolves prevents this class of failure.

Two live-verification gotchas (PR #318): the Ollama model sometimes flattens newlines out of tool-call bodies, so sign-off detection needs end-of-body fallbacks (valediction+name, sentence-boundary+name), not just standalone-line scans; and a DM test fired seconds after Render flips "live" can run on the draining old process — wait a few minutes before live-verifying a deploy.

**How to apply:** when Brian asks for a rule Kerri must "always follow," decide enforcement layer explicitly: agent memory/AgentProgram = advisory voice/judgment guidance; code in the send path = guarantees. Add new hard email rules to `Outbound::PreSendCheck#runChecks`-style methods with specs.
