When drafting any email, if the message promises a deliverable that already exists as a local file (media kit, one-pager, report, deck, PDF), ATTACH it to the send and word the email "I have attached ...", never "I will send ...".

**Why:** Brian's rule (2026-06-16). Drafting "I'll send the media kit" when the media kit is sitting on disk wastes a round-trip and looks unfinished. If we have it, it goes out with the email.

**How to apply (UPDATED 2026-07-11 — Drive IDs, not local paths):** The legacy local worker that read path-based `job.routing.attachments` was retired 2026-06-30; `SendApprovedDraftsJob` on Render is the only sender and can ONLY attach Google Drive files. At draft time: (1) upload the file to Drive if it's only local, (2) verify Drive `fileSize` equals the local byte count (a 6.7MB prospectus once truncated to 251 bytes), (3) use a clean client-facing Drive filename, (4) declare `ATTACHMENTS TO SEND: <exact Drive name> (Drive ID: <id>)` on the card — never a local path, or the card holds with `attachments_unresolved` (that stalled the Dassault card 3728e36d, 2026-07-11). Contract is codified in `agent-prompts/CLAUDE-ROUTINES.md` → "Email attachments contract". Canonical media kit (local source): `~/Projects/hwfyi-media-kit-2026/Hardware FYI Media Kit 2026.pdf`; Kinetic 2027 prospectus in Drive (CANONICAL as of 2026-07-11): `Kinetic-2027-Sponsor-Prospectus.pdf` (Drive ID `1gNDYsZKHLMDTvkbjRbKOPs0A6PR0h10w`, 9,849,148 bytes, flattened/viewer-proof). The Canva-exported originals ("(V3) (4)", "V3 Rev B") render with black/white patches in weak PDF viewers (Drive preview, Quick Look, Outlook) due to transparency groups/blend modes — never send a raw Canva export to a client; flatten first (PyMuPDF page→JPEG rebuild, recipe in the 2026-07-11 session). Only promise-to-send when the file genuinely does not exist yet (custom package menu not built, fresh metrics export, attendee list still to pull) — then the card's ⚠ line names exactly what is still owed and by whom.
