Brian received a new **Mac mini** (2026-06-24) and is porting his entire Kerri/KMG environment to it. Full runbook: `~/mac-mini-migration-plan.md` (local; readable from old Mac/phone during the move).

**Method: Apple Migration Assistant, Mac→Mac, during the mini's first-boot Setup Assistant — NOT iCloud.** Both machines are Apple Silicon, so it's a clean byte-for-byte account copy incl. keychain. iCloud only covers Documents/Desktop/Downloads + iCloud Drive; ~95% of the system (`~/.claude`, `~/.kerri-chief`, `~/Projects`, `/opt/homebrew`, LaunchAgents, hidden token folders) lives outside it and would be left behind or corrupted (same reason the brain was moved off iCloud in June). **Keep username `brianderario`** — hundreds of hardcoded `/Users/brianderario/...` paths.

**Footprint (~7GB core):** `~/.claude` 3.9G (18 live scheduled routines + 10 skills + settings/hooks + creds + memory), `~/.kerri-chief` 1.0G **LOCAL-ONLY no backup** (6 MCP bridge servers + 8 secret `.env`s + runtime/queue/state), `~/Projects` 1.8G (3 git-backed: kerrihq-rails/kerrios-agent-brain/kerri-console; ~14 LOCAL-ONLY irreplaceable dirs incl kerri-brand, kerrihq-website, kinetic-2027-growth), 6 always-on `com.kerri.*` launchd daemons + postgres@17 + ollama, plus ~12 hidden OAuth/token folders. The routines run **locally** on this Mac (they `cd ~/Projects/kerrios-agent-brain` + use local stdio MCPs), so the whole layer is machine-dependent — it does NOT keep running cloud-side if the Mac is gone.

**Biggest risk: double-run during cutover** — both Macs firing inbox-sweep / brain-push = double-sends + git conflicts. Fix: verify mini, THEN disable old Mac's routines+daemons, run mini solo 1 day, keep old Mac dormant ~1wk as fallback before wipe.

**Cloud-only (no migration, just re-auth):** Savant/kerrihq-rails prod (Render), GitHub, Cloudflare Pages, and all SaaS (Graph/Google/Apollo/Stripe/Mercury/beehiiv/Slack/Reclaim/Granola/DocuSign). Device-bound re-auth needed: Claude-in-Chrome pairing, Kerri Chrome profile + beehiiv login, macOS Privacy permissions (Accessibility/Screen/Automation).

ARCHITECTURE DECIDED 2026-06-24 (Brian): no SSD/cable available, so transfer is **direct Mac-to-Mac over Wi-Fi via Migration Assistant** (old laptop stays intact = the backup; no iCloud for the system, only personal Docs/Desktop which already sync). **Kerri lives ONLY on the mini** (Option 1); the laptop stays Brian's clean day-to-day driver with Kerri automation OFF. Mini config: auto-login + never-sleep + Screen Sharing on (so it runs headless and is viewable from the laptop without a monitor). Reach Kerri remotely (no Terminal/SSH for daily use): **Slack DM = primary** (the `kerri-slack-daemon`, `~/Projects/kerri-slack-daemon/index.js`, fires `claude -p` on DMs/@mentions, Socket Mode so it works behind home NAT, serves KerriHQ [full] + Hardware FYI [HWFYI-mail-only] workspaces, verified live pid 3115 2026-06-24); iMessage handoff = backup text line; email kerri@ = async task drop (sweep reads every 15 min weekdays); Screen Sharing = hands-on at home. KNOWN GAP to harden: kerri-slack-daemon has a 5-min `claude -p` timeout that makes long asks fail (repeated timeouts in `~/Library/Logs/kerri-slack-error.log`); fix = raise timeout + ack-immediately-then-follow-up. At cutover, disable the laptop's routines + 6 daemons (esp. its slack daemon, or it double-replies). Related: [[imessage_handoff]].
