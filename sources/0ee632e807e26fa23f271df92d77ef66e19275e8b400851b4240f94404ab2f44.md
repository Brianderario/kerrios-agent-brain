Wired Brian's **Granola meeting notes + transcripts** into the Savant agent (the Ollama `glm-5.2` agent behind the Kerri/Oliver Slack bots — see [[slack_agents_architecture]]) over Granola's public REST API. Shipped as [kerrihq-rails#197](https://github.com/kerrihq/kerrihq-rails/pull/197) (branch `feat/granola-api`, worktree `~/Projects/kerrihq-rails-superhuman`). Sibling to the Superhuman integration ([[superhuman-mcp-savant]]).

**Granola = API-key only** (Bearer `grn_…`, base `https://public-api.granola.ai/v1`, read-only: notes/transcripts/summaries). Its MCP server is OAuth-only and does NOT accept the key, so this is a native REST client (`GranolaClient`), not MCP. Key is in `~/.kerri-chief/secrets/granola.env` (never git/brain); on Render set env var `GRANOLA_API_KEY` on BOTH `kerrihq-rails` (web) + `kerrihq-queue` (worker). `GranolaClient.for_organization` reads the org IntegrationConnection api_key (provider `:granola`, enum 5, no migration) OR the env var.

Tools: `list_granola_meetings` (recent, optional title query + created_after) + `read_granola_meeting` (summary + transcript w/ speaker source + attendees). **Gating: Brian-only + KerriHQ Slack workspace** (`AccessPolicy.granola_email?` + `kerrihq_slack_workspace?`) — Granola mixes KMG, S&W, and personal meetings in one flat list with no folder filter, so Brian-only holds the S/W boundary. Read-only (no mutations); prompt says never copy Granola content into the brain.

Faraday gotcha fixed: base URL must be host-only (`https://public-api.granola.ai`) with `/v1` in each request path — a leading-slash path drops the base path → 404. (Reclaim's client avoids this only because its base has no path component.)

Verified: 209 specs green + live read-only run against the real Granola account; rubocop/brakeman clean. Also bumped `msgpack` 1.8.0→1.8.3 in this PR to clear a same-day bundler-audit CVE (CVE-2026-54522) that was failing scan_ruby on every branch incl. main.
