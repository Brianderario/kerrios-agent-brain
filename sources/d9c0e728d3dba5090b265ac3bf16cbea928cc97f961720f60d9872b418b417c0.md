Savant Console prod (`kerrihq-rails`) runs on Render and **auto-deploys on merge to `main`** (Blueprint default `autoDeploy: true`; no explicit flag in `render.yaml`). Merging a PR to main is usually all "deploy" requires — no manual trigger.

**API access:** `RENDER_API_KEY` lives in `~/.kerri-chief/secrets/render.env` (source it; NEVER print the value or put it in the brain/GitHub). Base: `https://api.render.com/v1`, `Authorization: Bearer $RENDER_API_KEY`.

**Service IDs:**
- web `kerrihq-rails` = `srv-d8kvn767r5hc739fjo9g`
- queue worker `kerrihq-queue` = `srv-d8kvnkcvikkc73c8cm6g` (runs ActiveJob incl. the `:agents` queue — background jobs need THIS live too, not just web)
- `kerri-voice-agent` = `srv-d95hda3tqb8s73erb1t0`

**Check a deploy:** `GET /services/<id>/deploys?limit=3` → each `deploy` has `status` + `commit`. Status flow: `build_in_progress` → `pre_deploy_in_progress` → `update_in_progress` → `live`. `pre_deploy` runs `db:prepare && db:seed` (`preDeployCommand`), so **migrations apply automatically on deploy**; a migration failure shows as a failed `pre_deploy`.

**Verify live:** `GET https://kerrihq-rails-xtua.onrender.com/up` → 200.

Related: [production only](feedback_production_only.md), [kerrihq-rails dev env](kerrihq_rails_dev_env.md), [brain architecture](kerrios_brain.md).

**Logs API:** `GET /v1/logs?ownerId=<tea-...>&resource=<srv-...>&text=...&startTime=...` (ownerId REQUIRED; param is `resource`, not `resourceIds`). One-off job stdout (`POST /services/<id>/jobs`) does NOT appear in this log stream — treat job output as unretrievable via API; if you need a value back, verify another way.
