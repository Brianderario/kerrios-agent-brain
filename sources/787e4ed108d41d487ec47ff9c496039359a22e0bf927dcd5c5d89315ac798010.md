On 2026-06-29 Brian asked to de-clutter the Savant `/brain` knowledge hub ("a mess, hard to parse"). Done + verified on production.

**What was wrong:** the `operations` domain was a 128-record junk drawer (64% of the 201 visible records); ~25 duplicate/fulfilled-candidate/dead-pointer records sat next to canonical truth; the team's real person profiles were wrongly stale; ~24 sponsor meeting recaps were buried in operations.

**What changed (all reversible — "hide" = `status: stale`, nothing deleted):**
- Hid 28 duplicate/junk records (the stray "Memory" index copy, two "Sponsor deal flow process" dups, two "KMG company structure" dups, 8 dead `stub-*` pointers to the retired KerriOS folders, KerriOS Brain Index/Routing, several self-marked-fulfilled candidates).
- Promoted 7 to canonical: full team profiles (Brian/Benji + restored Ari/Zach), KMG current priorities, pipeline-hygiene policy.
- Re-homed 42 records out of operations into the right hub cards.

**Result (active records per hub card):** operations 128→59, hardware_fyi 19→44 (gets its sponsor meetings), engineering 23→27, events 17→18, standard_works 10→12, **global 0→10 (new)**, **people 0→4 (new)**, finance 2; content/pipeline single-item cards folded away. Total visible 201→176; hidden 46→71.

**How it was executed:** the V1 API can't mutate canonical records (deliberate guardrail), so it ran as a Rails data task. PR [kerrihq-rails#192](https://github.com/kerrihq/kerrihq-rails/pull/192) (`lib/tasks/brain_cleanup.rake`, idempotent, `APPLY=1`) merged to main. Because the prod Docker build was already broken (see [[savant-prod-build-broken]]), the deploy didn't ship — so the apply ran via a **Render one-off job** (`POST /v1/services/<svc>/jobs`, inline `rails runner`, RENDER_API_KEY in `~/.kerri-chief/secrets/render.env`) against the live DB. Verified by re-pulling all 247 records via the V1 API and diffing vs the manifest: **0 mismatches**.

**To revert any item:** in Savant `/brain`, open the record and Promote it back (stale→canonical), or re-run the task logic with the record removed from the STALE list. Manifest of every change is in PR #192's description.
